# CV 연구성과 현행화

`_data/cv.yml`의 `patents`와 `papers`만 대상으로 한다. 먼저 `AGENTS.md`와 `doc/site-guide.md`를 읽고, 공개적으로 검증할 수 있는 정보만 반영한다.

## 작업 모드

- 사용자가 “현행화”, “업데이트”, “추가”를 요청하면 검증된 변경을 `_data/cv.yml`에 반영한다.
- 사용자가 “점검”, “확인”, “보고”만 요청하면 후보·차이·근거만 보고하고 파일을 수정하지 않는다.
- 특허·논문 이외의 프로필 또는 경력 정보는 후보 발견에만 사용하며, 사용자의 별도 요청 없이 수정하지 않는다.

## 기존 항목 확인

1. 각 특허는 `kr_number`, `us_number`, `publication_number`을 정규화한 뒤 개별 식별자로 검색한다. 공개 특허 데이터베이스와 특허청 기록을 우선하고, 상태·공개번호·출원일·등록일·제목·공개 링크를 대조한다.
2. 각 논문은 DOI를 소문자로 정규화하고 `https://doi.org/<doi>`로 확인한다. DOI 등록정보와 출판사·학회 공식 논문 페이지를 우선하여 제목, 저자, 연도, 학술지·학회, URL을 대조한다.
3. 기존 `contribution`처럼 공개 출처로 확인할 수 없는 개인 기여도는 추정하거나 자동 변경하지 않는다. 변경 후보가 있으면 사용자 확인 절차를 따른다.
4. 출처 간 내용이 충돌하거나 식별자가 여러 결과와 일치하면 항목을 자동 변경하지 않는다. 사용자 확인이 필요한지 판단하고, 확인할 수 없는 공개 사실은 검토 대상으로 보고한다.

## 신규 항목 발견과 검증

1. `_data/cv.yml`의 `profiles`에 있는 Google Scholar와 LinkedIn 공개 URL을 확인한다. 로그인 우회, 비공개 영역 접근, 자동화 차단 우회는 하지 않는다.
2. 발견한 후보를 제목, DOI, 특허 번호, 저자·발명자 목록으로 기존 항목과 비교한다. DOI는 공백·접두 URL을 제거하고 소문자로 비교하며, 특허 번호는 공백·구두점을 제거해 비교한다.
3. LinkedIn·Google Scholar는 후보 발견용으로만 사용한다. 새 항목은 아래의 독립적인 공개 근거가 있을 때만 추가한다.
   - 논문: DOI 등록정보 또는 출판사·학회 공식 논문 페이지
   - 특허: 공개 특허 기록 또는 특허청 기록
4. 저자·발명자 동일성이 모호하면 사용자 확인 절차를 따른다. 공개 여부를 확인할 수 없으면 추가하지 않고 검토 대상으로 보고한다. 새 미공개 특허와 비공개 문서 URL은 추가하지 않는다.

## 사용자 확인

1. 기여도, 저자·발명자 동일성, 저자 순서, 주저자 여부처럼 공개 근거만으로 확정할 수 없는 값은 사용자에게 질문한다.
2. 질문마다 항목 제목·식별자, 현재 값, 발견한 후보 값, 공개 근거 링크를 함께 제시한다. 여러 항목이 있으면 한 번에 묶어 확인받는다.
3. 사용자의 명시적 답변이 있으면 `contribution`, `authors`, `is_first_author` 등 해당 개인 정보를 반영한다. 답변이 없으면 기존 값을 유지하고 신규 항목은 보류한다.
4. 사용자 답변만으로 특허를 공개 상태로 바꾸거나 초록·외부 링크를 추가하지 않는다. 이 정보는 공개 특허 기록으로 별도 확인한다.

## 데이터 반영 규칙

- 특허는 공개 상태에 맞춰 `is_public`, `is_registered`, `status`, 날짜, 번호, `publication_number`, `abstract`, `url`을 갱신한다. 공개 특허만 `abstract`와 `url`을 추가한다.
- 논문은 `title`, `year`, `authors`, `venue`, `description`, `keywords`, `url`을 공식 근거에 맞춰 갱신한다. DOI가 있으면 `url`에 표준 DOI URL을 사용한다.
- `is_first_author`는 공식 저자 순서에서 Donghun Jeong이 첫 저자임을 분명히 확인했을 때만 설정하거나 변경한다. 저자 동일성 또는 순서가 모호하면 사용자에게 확인한 뒤 반영한다.
- 날짜는 기존 YAML 형식을 유지한다. 새 항목은 기존 데이터 구조와 들여쓰기 규칙을 따른다.
- 표시 순서는 템플릿이 특허의 등록 여부·날짜와 논문의 주저자 여부·연도로 계산하므로, 정렬 로직을 바꾸지 않는 한 새 배열 항목은 추가만 한다.
- 데이터 필드나 표시·정렬 규칙을 바꾸면 같은 변경에서 `doc/site-guide.md`를 갱신한다.

## 검증과 보고

1. 각 변경 또는 신규 항목에 사용한 공개 출처 링크를 기록한다.
2. YAML을 검토한 뒤 `$verify-cv-site-content`를 사용하고 `bundle exec jekyll build`를 실행한다.
3. 결과에는 갱신·추가·변경 없음·검토 필요 항목을 구분하고, 각 항목의 식별자와 근거 링크, 사용자 확인 반영 내용, 빌드 결과를 간결히 보고한다.
